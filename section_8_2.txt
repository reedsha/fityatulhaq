หน้า 39 / 42 9. ข้อกําหนดที่ไม่ใช่เชิงฟังก์ชัน (Non-Functional Requirements) 9.1 การรองรับหลายอุปกรณ์ (Responsive Design) • ต้องแสดงผลได้ดีทั้งบน Desktop, Tablet และ Mobile (Breakpoint มาตรฐาน: 1280px / 768px / 375px) • เมนู Header ปรับเป็น Drawer บนมือถือ ตามที่ระบุในบทที่ 3 9.2 ประสิทธิภาพ (Performance) • เวลาโหลดหน้าแรก (First Contentful Paint) ไม่เกิน 2.5 วินาที บนอินเทอร์เน็ตมือถือทั่วไป • ใช้ Image Optimization/Lazy Loading สําหรับรูปภาพและวิดีโอในหน้าที่มีสื่อจํานวนมาก (เช่น หน้าค่ายกิจกรรม, แกลเลอรี) • ใช้ Caching/CDN สําหรับเนื้อหาสาธารณะที่ไม่เปลี่ยนแปลงบ่อย (ข่าวเก่า, บทความ) 9.3 ความปลอดภัย (Security) • ป้องกัน SQL Injection / XSS ผ่าน ORM (Prisma) และการ Sanitize ข้อมูล Input ทุกจุดที่รับเนื้อหาจากผู้ใช้ (เว็บบอร์ด, ฟอร์มติดต่อ) • HTTPS บังคับทุกหน้า (SSL/TLS) • แยก Secret/Environment Variables ของเว็บที่ 1 ออกจากเว็บที่ 2 อย่างเด็ดขาด • ปฏิบัติตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA) ในการเก็บข้อมูลสมาชิกและผู้ถามคําถาม Youth Care 9.4 การค้นหาและ SEO • หน้าเนื้อหาสาธารณะ (ข่าว, บทความ, หลักสูตร ฯลฯ) ต้องรองรับ Server-Side Rendering (SSR) หรือ Static Generation เพื่อให้ติดอันดับการค้นหา Google ได้ดี • มี Meta Tags, Open Graph Image สําหรับแชร์ลง Social Media ในทุกหน้าเนื้อหา • มี Sitemap.xml และ robots.txt มาตรฐาน 9.5 การเข้าถึงได้ (Accessibility) • รองรับการอ่านผ่าน Screen Reader เบื้องต้น (Alt text รูปภาพ, Semantic HTML) • ขนาดตัวอักษรและคอนทราสต์สีเป็นไปตามมาตรฐาน WCAG 2.1 ระดับ AA ขั้นตํ่า 9.6 การรองรับเบราว์เซอร์ • รองรับ Chrome, Safari, Edge, Firefox เวอร์ชันล่าสุด 2 เวอร์ชันย้อนหลัง • รองรับ Safari บน iOS และ Chrome บน Android เป็นหลัก เนื่องจากกลุ่มเป้าหมายเป็นเยาวชนที่ใช้งานผ่านมือถือเป็นหลัก
